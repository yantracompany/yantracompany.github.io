Hello, GenAI

We just moved our site to Angular 18 with Server-Side Rendering (SSR) and prerender, and we’re hosting everything on GitHub Pages.

This setup lets us keep the simplicity of static hosting while still shipping real HTML per route — which is a big win for SEO and performance.

Why We Switched

For a while, we relied on client-side rendering only. It was quick to deploy, but search engines weren’t always happy with our JavaScript-heavy pages. With Angular 18’s improvements in SSR and prerender, we finally had a smooth path to deliver HTML-first content without sacrificing the developer experience.

Benefits of SSR + Prerender

  • 🔍 SEO-friendly: search crawlers can now index real content instantly.
  • ⚡ Performance: first paint is faster since HTML comes pre-generated.
  • 🛠️ Static hosting: GitHub Pages remains free, fast, and reliable.
  • 📦 Simpler deployments: just push to main, and the site updates.

Hosting on GitHub Pages

One of the challenges was figuring out how to combine Angular’s SSR output with GitHub Pages’ static hosting. The solution was prerendering routes ahead of time, so GitHub Pages just serves static files. It’s a nice balance — no server costs, but still SEO-friendly pages.

What’s Next

We’re looking into adding incremental prerendering so that newly added content can be generated on demand. Plus, we plan to monitor performance metrics like Largest Contentful Paint (LCP) and Core Web Vitals to make sure we’re actually seeing the improvements we expect.

“Static hosting doesn’t have to mean static content. With the right tools, you can have the best of both worlds.”

Overall, the migration has been smooth, and we’re excited about the scalability of this setup. It’s lightweight, SEO-friendly, and cost-effective — exactly what we wanted.
